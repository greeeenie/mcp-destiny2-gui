# mcp-destiny2-gui

Десктопный голосовой оверлей по Destiny 2: окно поверх игры, разговор с ассистентом голосом
и действия в инвентаре через инструменты MCP. Ключ выбранного LLM-провайдера задаёт игрок;
он хранится локально под DPAPI и передаётся серверу только на время чат-запроса.

Проектное решение целиком — в [`docs/plan.md`](docs/plan.md). Здесь только то, что нужно,
чтобы собрать и запустить.

## Требования

| Что | Версия |
| --- | --- |
| Windows | 10/11 (DPAPI и `GetAsyncKeyState` — Windows-only) |
| JDK для сборки | 21 |
| Аккаунт | на `https://duoxik.space/mcp-destiny2-client` |
| Destiny 2 | режим **«оконный без рамки»** |

В exclusive fullscreen оверлей не виден — это ограничение ОС, а не приложения.

## Сборка и запуск

```bash
./gradlew build          # компиляция и тесты
./gradlew run            # запуск из исходников
./gradlew packageMsi     # установщик .msi (нужен WiX Toolset 3.x в PATH)
```

Если JDK 21 не в `JAVA_HOME`, укажите его явно:

```bash
JAVA_HOME="C:/Users/<вы>/.jdks/liberica-21.0.11" ./gradlew build
```

## Первый запуск

1. Консоль открывается сама. На вкладке **Аккаунт** зарегистрируйтесь или войдите.
   Имя пользователя становится именем MCP-профиля: 5–20 символов, латиница, цифры, `_` и `-`.
2. Вкладка **Звук**: выберите микрофон и вывод, нажмите «Эхо-тест: 5 секунд» — записанное
   должно проиграться чисто, без щелчков и без ускорения.
3. Вкладка **Голос**: выберите клавишу push-to-talk (по умолчанию Right Alt) и нажмите
   «Включить голос».
4. Если Bungie не привязан, на вкладке **Аккаунт** нажмите «Привязать Bungie», откройте
   ссылку и вернитесь — статус подтянется сам.

Дальше: зажали клавишу — говорите, отпустили — ассистент отвечает **текстом в оверлее**.
Нажатие клавиши во время ответа прерывает его и снова открывает микрофон.

## Ответ текстом, а не голосом

По умолчанию озвучка выключена, и оверлей просит у Inworld только текстовую модальность —
синтез речи не выполняется и не тарифицируется. Ответ рисуется в HUD как Markdown: заголовки,
списки, таблицы с выравниванием колонок, код, цитаты, кликабельные ссылки.

Включить голос можно на вкладке «Голос» → «Озвучивать ответы» (вернётся и звук, и плата за него).

**Чтобы в ответах появились таблицы, промпт на сервере должен просить Markdown.** Оверлей
разметку только отображает — формат ответа задаёт системный промпт в `application.yaml`
бэкенда, и менять его оверлей права не имеет (§3.2 плана). Пока промпт написан под голосовые
ответы, ассистент будет отвечать сплошной прозой — и это будет видно как обычный абзац.

## Где что лежит

| Что | Где |
| --- | --- |
| Настройки | `%LOCALAPPDATA%\mcp-destiny2-gui\settings.json` (открытый текст) |
| Сессия бэкенда | `%LOCALAPPDATA%\mcp-destiny2-gui\session.bin` (DPAPI, только этот пользователь) |
| Ключи провайдеров | `%LOCALAPPDATA%\mcp-destiny2-gui\provider-api-keys.bin` (DPAPI) |
| Логи | `%LOCALAPPDATA%\mcp-destiny2-gui\logs\overlay.log` (ротация, без PCM и текстов реплик) |

JWT Inworld на диск не пишется вовсе — только в памяти, до конца сессии.

## Если что-то не работает

**Нет звука или микрофон не тот.** Вкладка «Звук» → «Обновить список» → выберите устройство
явно и прогоните эхо-тест. JavaSound фиксирует устройство в момент открытия линии и не следует
за сменой системного «по умолчанию»; устройство, воткнутое после запуска, появится в списке
только после перезапуска приложения.

**Ассистент не отвечает после отпускания клавиши.** Вкладка «Голос» → включите «Закрывать ход
явным commit»: значит, хвоста тишины в 400 мс вашему VAD не хватает.

**Ассистент отвечает сам себе.** Вы на колонках с включённым hands-free. Выключите hands-free
или наденьте наушники: акустического эхоподавления в оверлее нет намеренно — микрофон и
колонка никогда не активны одновременно только в push-to-talk.

**Клик по HUD отбирает фокус у игры.** Такого быть не должно: окно нефокусируемое. Если
случилось — приложите лог, это баг.

**Оверлея не видно поверх игры.** Проверьте, что Destiny 2 в режиме «оконный без рамки».

## Что оверлей не делает

Никаких хуков DirectX/OpenGL, инъекций DLL, чтения памяти игры и синтеза ввода в игру.
Единственное касание системного ввода — чтение состояния одной клавиши через
`GetAsyncKeyState`. Это сознательное ограничение из-за BattlEye (риск 1 плана).
